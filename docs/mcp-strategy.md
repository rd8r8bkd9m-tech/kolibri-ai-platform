# MCP стратегия и границы контроля

## Цели

- Отделить инструменты управления инфраструктурой (tools),
  ресурсы состояния (resources) и операционные подсказки (prompts).
- Ввести единый API surface, удобный для автоматизации и расширения.

## Практика первого этапа

- Сохранить строгую прослеживаемость вызовов (trace_id/correlation_id).
- Никаких секретов в payload-инструментах.
- Любой tool-call должен проходить policy gate.

## Контролируемые домены

- `fleet.*`
- `tasks.*`
- `nodes.*`
- `events.*`
- `artifacts.*`
