# Telegram Command Contract

Task id: P1_TELEGRAM_OWNER_GATEWAY_STABILIZATION_2026_07_02
Date: 2026-07-02
Scope: owner Telegram bot command contract for the stabilized gateway.

## Global Rules

- The gateway accepts commands only from configured owner user IDs in private chats.
- All owner-visible text is Russian, concise, and safe for Telegram.
- Commands are routed through existing gateway and Control Plane APIs only.
- Command handlers must not call live Telegram delivery-state mutation methods.
- Command handlers must not expose raw internal IDs, paths, logs, prompts, secrets, or env details.
- Tests must use fake Telegram and fake Control Plane clients unless a separate owner-approved live smoke task exists.

## Commands

| Command | Owner intent | Backend action | Owner-visible result | Safety notes |
| --- | --- | --- | --- | --- |
| `/start` | Begin owner chat | No Control Plane mutation | Plain-language help | No command inventory or internal IDs |
| `/help` | Explain usage | No Control Plane mutation | Plain-language help | No raw task syntax requirements beyond owner language |
| `/task <objective>` | Submit work | Create Control Plane task envelope | Human acknowledgement | On failure, redacted Russian fallback |
| Free text task intent | Submit work | Create Control Plane task envelope | Human acknowledgement | Intent classifier must avoid treating simple questions as work |
| Free text chat | Ask or follow up | Create chat task or answer from safe context | Human answer or fallback | Runner failures are redacted |
| Image intent | Generate image | Create image task envelope | Human acknowledgement, later image if completed | Caption is cleaned before delivery |
| `/status <task>` | Inspect known task | Read task from Control Plane | Sanitized status card | Broader payload redaction remains a residual risk |
| `/cancel <task>` | Cancel known task | Call Control Plane cancel | Sanitized status card | Action is owner-only; live destructive deploy actions are out of scope |
| `/retry <task>` | Retry known task | Read old task and create copied envelope | Sanitized status card | Needs continued owner-safe review before broader rollout |
| `/nodes` | Inspect fleet | Read Control Plane nodes | Role/count summary | No raw node IDs or private host details |
| `/agents` | Inspect agents | Read Control Plane nodes/runners | Role/count summary | No raw agent IDs, PIDs, or runner internals |
| `/queue` | Inspect queue | Read Control Plane tasks | Count/status summary | No task IDs, raw queue records, owner prompts, or paths |

## Envelope Requirements

Task, chat, and image submissions must include:

- `task_id` and `idempotency_key` generated by the gateway.
- Source metadata marking Telegram as the origin.
- The owner message or objective needed by the executor.
- A bounded retry count.
- Existing Control Plane-compatible kind/capability fields.
- Conversation/factory context only after sanitization suitable for the executor path.

Owner-visible replies must not echo the generated `task_id`.

## Failure Contract

- Control Plane create/read/cancel failures must be caught at command boundaries where practical.
- The owner receives a human Russian fallback.
- Raw exception text, HTTP details, stack traces, command lines, runner prompts, and paths stay out of Telegram.
- The run docs should record residual gaps instead of adding broad runtime changes inside this docs-only artifact gate.

## Validation Contract

Required focused validation:

```bash
pytest -q tests/test_telegram_gateway.py tests/test_agent_host_telegram_chat.py
```

Passing criteria:

- Fake Telegram messages for command summaries contain no forbidden markers.
- Fake Control Plane failures produce redacted Russian fallbacks.
- Agent Host chat failure handling does not leak runner prompts or raw tool output.
