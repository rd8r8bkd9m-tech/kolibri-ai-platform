# План разработки мобильного клиента Kolibri (React Native) по мотивам ChatGPT

Дата: 2026-08-13
Статус: утверждён к исполнению
База: `apps/kolibri-mobile` (Expo SDK 57, React Native 0.86, Expo Router,
`@assistant-ui/react-native`, AG-UI)
Дизайн-референс: `docs/design-evidence/mobile-chatgpt/` (20 скриншотов,
`interaction-notes.md`, `state-matrix.md`)
Продуктовый контракт: `docs/MOBILE_INTERFACE.md`

## 1. Цель

Довести нативный мобильный клиент Kolibri до интерфейса, который повторяет
геометрию, состояния и интеракции ChatGPT mobile (пустой чат, composer,
стриминг, карточки результатов, сайдбар, проекты, библиотека, удалённые
источники), но остаётся продуктом Kolibri: серверная история, единый
assistant-ui/AG-UI runtime и реальные данные, а не декорация по мотивам
скриншотов.

## 2. Границы scope

### Внутри scope

- Светлая и тёмная темы (true white / true black), персистентный выбор
  `system | light | dark`.
- Пустой и активный чат: header, стартовые действия, история, результат
  и стриминг.
- Composer ChatGPT-типа: капсула, авто-рост, нижний ряд действий,
  send/stop, вложения, выбор модели/усилия, диктовка, live voice-контрол.
- Сайдбар с destinations, поиск, новый чат, настройки; back-переходы
  между чатом и списком.
- Экран проектов, библиотеки (grid), удалённых источников, sort-sheet
  и connection settings.
- Жесты: long-press на диалоге, haptics, Reduce Motion.
- Нативная безопасность: refresh token в SecureStore, access token в памяти.

### Вне scope (осознанно)

- Репликация бренда/логотипов/текстов ChatGPT.
- Изменение desktop-интерфейса V3 из-за мобильной работы.
- Локальная офлайн-история, кэш-партиалы и поддельные данные.
- Покупки, подписки, приватность/security-экраны (только read-only
  в дизайн-исследовании).
- WebView-обёртки: интерфейс остаётся нативным React Native.

## 3. Архитектурные принципы

1. **Единый runtime сообщений.** Вся отправка, стриминг, остановка и
   Generative UI — через официальный assistant-ui/AG-UI runtime; никаких
   вторых текстовых состояний и локальных фейков.
2. **Сервер — единственный источник истории.** Диалоги, pin/archive/delete,
   проекты, библиотека и удалённые источники живут на V3 backend; клиент
   только рендерит и отправляет операции.
3. **Реальность вместо декора.** Каждый элемент референса, попавший в
   интерфейс, обязан быть рабочим контролом или осознанно скрытым;
   скриншотная имитация запрещена.
4. **Слои.** Транспорт тонкий (`src/product-chat/client.ts`), продуктовые
   контракты в `src/product-chat/contracts.ts` и `src/verticals/`,
   переиспользуемый UI в `components/`, примитивы в `components/ui/`.
5. **Capability gates.** Vertical surfaces активируются только через
   compile-time registry (`src/verticals/registry.ts`) + capability +
   entitlement; сервер не может включить неизвестный renderer.
6. **Тема до гидрации.** Выбор темы применяется до первого кадра во избежание
   цветовой вспышки; iOS status bar, клавиатура и home indicator остаются
   у операционной системы.
7. **Нативные чувства.** Haptics, safe areas, Android Back, Reduce Motion,
   accessibility-метки и hit-таргеты ≥ 44 px проверяются на устройстве.

## 4. Фазы

### Фаза 1 — Shell, header и сайдбар (экраны 01, 11, 18–20)

- Header пустого чата: hamburger слева, centered «Чат» semibold + chevron,
  new-chat справа; после первого сообщения — edit + overflow капсула.
- Токены геометрии: контроль 38–40 px, composer inset 18 px, капсула 78 px.
- Сайдбар как на референсе: скруглённый приподнятый край, без scrim,
  destinations (Проекты, Библиотека, Удаленно), footer с поиском, новым
  чатом и настройками.
- Навигация: expo-router drawer, закрытие по свайпу/нажатию вне,
  focus trap и возврат фокуса, Android Back.
- Back-переходы: направленная анимация без потери состояния чата.
- Safe areas сверху и снизу; статус-бар — системный.

### Фаза 2 — Composer и ввод (экраны 02, 03, 06, 04, 07)

- Однорядная капсула «в один этаж»: plus, input (flex), выбор модели/усилия,
  диктовка, live voice-контрол; авто-рост input до 4 строк, капсула растёт
  вверх, контролы остаются на месте.
- send — синий круг 30 px, morph в stop square при стриминге без relayout.
- Вложения: `expo-document-picker` + `/v1/attachments`, bounded upload,
  idempotency, чипы в composer.
- Keyboard avoidance iOS/Android; haptics при отправке/остановке.

### Фаза 3 — Сообщения, стриминг и результаты (экраны 05, 08–10)

- User-баблы справа; проза ассистента слева с тем же inset, что и карточки.
- Карточки из AG-UI `data`-part'ов (погода, генерация изображений) с
  безопасным Fallback для неизвестных типов; прогресс берётся из runtime.
- Scroll-to-bottom: 32 px circular над composer, появляется при скролле вверх.
- Stop из runtime; copy «Рассуждение остановлено» — только как наблюдаемый
  текст продукта.

### Фаза 4 — Проекты, библиотека, удалённые источники (экраны 12–16)

- Проекты: tabs, строки, pin-state, add-действие, нижний поиск.
- Библиотека: category tabs, двухколоночный grid, нижний поиск.
- Удалённые: connection chips, секции, нижний поиск и «Чат».
- Sort-sheet и connection settings: trailing/full-height sheets, закрытие
  по свайпу вниз/назад.
- Поверхности активируются сервером через capability/entitlement;
  без доступа показывается честный boundary, а не заглушка.

### Фаза 5 — Тема, жесты, доступность

- Light/dark/system; true white/black; применение до гидрации; переключение
  из «Внешний вид» без перезагрузки.
- Long-press диалога ~250 мс: меню «Закрепить/Архивировать/Удалить»,
  haptic, отмена при движении.
- Reduce Motion: отключает лишние анимации, оставляет функциональную
  навигацию.
- Accessibility: метки и роли для всех контролов, focus management
  в сайдбаре и sheets; outline-иконки, filled — только live/send/stop.

### Фаза 6 — QA и финальная проверка

- Скриптовые тесты на новое поведение (статические проверки контрактов
  и состояния).
- Проверка работоспособности на web-вьюпорте и нативном устройстве.

## 5. Критерии успеха

1. Мобильный клиент повторяет референсные экраны 01–16 и 18–20 в светлой
   и тёмной темах; каждый элемент — рабочий.
2. Чат, стриминг, остановка, вложения, проекты, библиотека и удалённые
   источники работают с данными V3 backend; истории не дублируются локально.
3. Неизвестные data-типы рендерятся через объяснимый Fallback, а не падают.

## 6. Риски и митигации

| Риск | Митигация |
| --- | --- |
| Часть состояний (клавиатура, long-press, меню модели) не замерена | Фиксируется решение «реализуем по notes/state-matrix», остальное — вручную на устройстве |
| Стриминг тяжёлых карточек тормозит JS-поток | Reanimated/worklets, мемоизация сообщений |
| «По мотивам» сползает в копирование ChatGPT-брендинга | Контракт из `MOBILE_INTERFACE.md`: меняется геометрия, не продукт |
| Сайдбар/sheets конфликтуют с expo-router drawer | Управляемый drawer-контент с focus trap |
| Back-переходы теряют draft/скролл | Состояние чата хранится в runtime |
