# Единый стандарт разработки Kolibri V3

Этот документ задаёт минимальный проверяемый стандарт для всех активных
контуров V3. Он дополняет, но не заменяет runtime- и release-инварианты из
`AGENTS.md`.

Структуру модулей и направление зависимостей определяет
[`PROJECT_MAP.md`](PROJECT_MAP.md), канонических владельцев данных —
[`SOURCE_OF_TRUTH.md`](SOURCE_OF_TRUTH.md), а ежедневный workflow и Definition
of Done — [`CONTRIBUTING.md`](../CONTRIBUTING.md).

## Базовые правила

- Изменения продукта выполняются только внутри `kolibri-v3/`.
- TypeScript остаётся в строгом режиме; новые обходы типов (`any`,
  `@ts-ignore`) требуют локального обоснования.
- Python-код должен проходить Ruff и `compileall`; публичные границы должны
  иметь явные типы и проверять входные данные.
- Rust-код должен проходить `rustfmt`, Clippy с `-D warnings` и тесты.
- Секреты не коммитятся. В примерах используются только фиктивные значения.
- Бизнес-правила и исправления регрессий сопровождаются тестом на ближайшем
  уровне: unit, contract или integration.
- Новый архитектурный контур не появляется «по ходу реализации»: сначала
  принимается ADR из [`docs/adr/`](adr/README.md).
- Форматы файлов и отступы определяет `.editorconfig`; автоформатирование не
  должно смешиваться с функциональным изменением в одном diff.

## Канонические проверки

Быстрый обязательный gate для каждого изменения:

```bash
npm run verify
```

Он проверяет Python, web-контракты и оба Rust-пакета. Полный локальный gate:

```bash
npm run verify:full
```

Полный gate дополнительно собирает Next.js и проверяет native mobile. Он не
запускает development runtime и не изменяет owner-сессию.

## Порядок развития правил

Линтеры вводятся без массового автоматического переписывания существующего
кода. Сначала правило включается для всей базы и устраняется текущий долг,
затем оно становится обязательным gate. Такой порядок сохраняет обозримые
diff, авторство и возможность безопасного отката.
