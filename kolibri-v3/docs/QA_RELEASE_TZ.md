# V3: единый web/PWA runtime и QA-релиз

## Цель

Выпускать Kolibri V3 через один публичный origin и один внешний порт
`3103`. Клиент выбирается маршрутизатором по запросу, но desktop и mobile
используют один backend, одну авторизацию, одну сессию и один набор продуктовых
контрактов.

## Runtime-контракт

| Контур | Внешний адрес | Внутренний upstream | Назначение |
| --- | --- | --- | --- |
| Gateway | `127.0.0.1:3103` | — | единственная точка входа браузера |
| Desktop | только через gateway | `127.0.0.1:3104` | Next.js desktop/PWA |
| Mobile | только через gateway | `[::1]:4104` | Expo/React Native Web mobile |
| API | `127.0.0.1:8002` | — | V3 backend, миграции и auth |

Прямой доступ к `3104` и `4104` не является пользовательским контрактом.
`/app?client=mobile` и мобильный user-agent должны открывать mobile-клиент,
а обычный `/app` — desktop-клиент. Оба клиента обязаны обращаться к одному
`8002` и не содержать отдельного фиктивного адаптера.

## QA-профиль

### Общие проверки

1. `dev-stack` запускается только из `kolibri-v3/`.
2. Preflight сообщает последнюю миграцию, `platform_owner=1` и instance id.
3. `GET /v1/health` возвращает `status=ok`, `service=kolibri-v3`.
4. Gateway возвращает HTTP 200 для desktop и mobile через `3103`.
5. В консоли браузера нет `error`; предупреждения классифицируются и не
   маскируют ошибки.
6. API-запросы не получают неожиданные `401/403/422/5xx`.

### Desktop (Next.js)

- восстановление существующей owner-сессии;
- открытие и переключение двух бесед без вспышки/возврата в новую беседу;
- прокрутка истории и сайдбара;
- ввод сообщения, отправка, streaming ответа и остановка генерации;
- запрос, который должен вернуть обычный текст, и запрос на интерактивную
  смету;
- открытие разделов «Рабочий стол», «Проекты», «Документы», «Справочники»;
- отсутствие запросов к `4103`, старому backend или legacy-путям.

### Mobile (Expo/React Native Web)

Проверять в viewport iPhone 390×844 через тот же `3103`:

- открытие `/app?client=mobile` и мобильный user-agent;
- hamburger: открыть/закрыть меню, выбрать беседу, вернуться в чат;
- вертикальная прокрутка списка бесед и ленты сообщений;
- фокус composer, ввод, отправка, streaming ответа и отмена;
- кнопки вложения, микрофона и питомца не ломают layout;
- переход в личный кабинет и выход;
- отсутствие `ResizeObserver`/hydration/route errors и необработанных Promise.

## Правило исправлений

Каждый найденный дефект фиксируется в canonical V3-коде, покрывается
регрессионным тестом и проверяется в обоих клиентах. Нельзя чинить проблему
перенаправлением на legacy-код, подменой backend или изменением UI только под
одного агента. Изменения в gateway/runtime не должны менять продуктовую
типографику и иконографику.

## Release gate

Перед передачей результата должны быть приложены:

- команды и версии процессов (`3103`, `3104`, `4104`, `8002`);
- результаты typecheck и targeted runtime tests;
- browser QA для desktop и mobile с URL и временем проверки;
- список предупреждений, которые подтверждены как dependency-level и не
  влияют на функциональность;
- результат `npm run verify` с отдельным указанием pre-existing нарушений,
  если они не относятся к данной задаче.
