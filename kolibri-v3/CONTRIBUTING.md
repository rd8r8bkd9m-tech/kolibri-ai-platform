# Разработка Kolibri V3

## Рабочий цикл

1. Прочитать `AGENTS.md`, `docs/PROJECT_MAP.md` и источник истины затронутого
   домена.
2. Сформулировать один проверяемый результат и минимальный набор файлов.
3. Для архитектурного изменения сначала создать ADR.
4. Реализовать изменение в каноническом контуре, не копируя legacy-код.
5. Добавить тест регрессии на ближайшей границе.
6. Выполнить `npm run verify`; перед release-кандидатом —
   `npm run verify:full`.

## Definition of Done

- у данных и контракта ровно один владелец;
- соблюдены направления зависимостей из `PROJECT_MAP.md`;
- ошибки и недоступные authorities не маскируются demo/fallback данными;
- изменение схемы имеет миграцию и проверку совместимости;
- пользовательское поведение покрыто тестом;
- документация обновлена, если изменились команды, структура или контракт;
- diff не содержит секретов, runtime state, build output или несвязанных
  форматирующих изменений;
- обязательные gates проходят.

## Размер изменения

Предпочтителен вертикальный, откатываемый slice: контракт → серверное
поведение → клиент → тест. Массовое перемещение файлов, переименование и
функциональное изменение не смешиваются без явного плана миграции.
