TITLE: Machine-Readable Kolibri Brain
PRIORITY: P0
MODE: APPLY_IMMEDIATELY_NO_WAIT

This directive extends all previously received owner directives.

Do not stop, pause, cancel, or duplicate existing work.

Continue:

- remote factory operation;
- network convergence;
- node repairs;
- Telegram Mini App;

All implementation must be performed by real remote agents through the

======================================================================
1. PRIMARY OBJECTIVE
======================================================================

Build a machine-readable central brain for Kolibri.

Every owner instruction received through:

- Codex App;
- Telegram;
- Kolibri Web UI;
- Control API;
- future ChatGPT integration;

must be automatically converted from natural language into a validated,
versioned, machine-readable execution contract.

Required pipeline:

owner natural-language instruction
→ immutable raw directive
→ structured directive
→ schema validation
→ dependency detection
→ conflict detection
→ policy evaluation
→ root goal
→ task graph
→ scheduling
→ execution
→ evidence
→ verified lesson
→ shared knowledge

The owner must not manually create YAML, JSON, branches, servers, or task
dependencies.

The system must translate owner intent into machine-readable structures
automatically.

======================================================================
2. DO NOT BUILD A SINGLE FRAGILE BRAIN CONTAINER
======================================================================

“Kolibri Brain” is one logical service, but it must not be one physical
single point of failure.

Deploy the brain as cooperating services:

- kolibri-directive-compiler;
- kolibri-brain-api;
- kolibri-workflow-service;
- kolibri-knowledge-service;
- kolibri-policy-service;
- kolibri-artifact-service;
- kolibri-event-service;
- kolibri-reconciler;
- kolibri-observability.

Primary runs the active Control Plane.

Home runs:

- active compute;
- knowledge replica;
- artifact replica;
- standby Control Plane.

A third stable node acts as consensus/witness where required.

Do not introduce a hypervisor as a mandatory dependency.

Use:

- OCI containers;
- systemd;
- Nomad scheduling;
- isolated workspaces;
- resource limits.

Use virtual machines only for tasks requiring stronger isolation than
containers can provide.

======================================================================
4. DIRECTIVE COMPILER
======================================================================

Create service:

kolibri-directive-compiler.service

API:

POST /v1/directives
GET  /v1/directives
GET  /v1/directives/{directive_id}
POST /v1/directives/{directive_id}/compile
POST /v1/directives/{directive_id}/activate
POST /v1/directives/{directive_id}/pause
POST /v1/directives/{directive_id}/supersede
GET  /v1/directives/{directive_id}/evidence

Compilation stages:

1. Save raw instruction.
2. Detect language.
3. Extract owner intent.
4. Identify objectives.
5. Identify constraints.
6. Identify acceptance criteria.
7. Identify required capabilities.
8. Identify dependencies.
9. Identify conflicts with active directives.
10. Select execution mode:
    - SIMPLE;
    - MEDIUM;
    - COUNCIL.
11. Estimate task count and resources.
12. Apply policy.
13. Generate RootGoal.
14. Generate initial task DAG.
15. Validate every document against JSON Schema.
16. Calculate SHA-256.
17. Store compiled contract.
18. Register it in Control Plane.
19. Emit an event.
20. Start execution immediately.

The language model may propose structured output, but unvalidated output must
never enter execution.

Required validation:

- JSON Schema;
- semantic validators;
- budget validator;
- recursion validator;
- permission validator;
- dependency validator;
- conflict validator;
- duplicate detector.

Invalid directives must not silently disappear.

They receive:

- INVALID;
- NEEDS_REPAIR;
- or BLOCKED;

with an exact reason.

6. ROOT GOALS AND TASK GRAPH
======================================================================

Every activated directive creates one or more RootGoals.

RootGoal must contain:

- root_goal_id;
- directive_id;
- objective;
- acceptance criteria;
- priority;
- current phase;
- task graph;
- budgets;
- deadline;
- owner controls;
- evidence;
- final result.

Tasks form a directed acyclic graph.

Every task contains:

- root_task_id;
- task_id;
- parent_task_id;
- dependencies;
- objective;
- acceptance criteria;
- task_type;
- required capabilities;
- assigned agent;
- assigned node;
- budget;
- recursion depth;
- idempotency key;
- lease;
- heartbeat;
- state;
- attempts;
- artifacts;
- evidence.

Default recursion limits:

max_depth: 5
max_children_per_task: 20
max_active_children: 10

The compiler may create additional tasks during execution when:

- a bug is discovered;
- a test fails;

- a node fails;
- research identifies a required compatibility task.

All generated tasks must preserve root_goal_id and provenance.

======================================================================

Do not replace the currently working Factory Runtime in one destructive
migration.

Use Temporal first for new RootGoals and long-running orchestration:

- directive execution;
- recursive task trees;
- swarm councils;
- review cycles;
- staging and release;
- node repair;
- disaster recovery;
- periodic reconciliation.

Existing task execution may continue through the current Control Plane until

Migration:

4. Test server restart.

8. Verify zero duplicate effects.

history.

======================================================================
12. NO ROUTINE SSH EXECUTION
======================================================================

After bootstrap, ordinary Factory operation must not use SSH.

Workers must:

1. start as persistent services;
2. connect outbound to the Control Plane/event layer;
3. register capabilities;
4. receive tasks from the queue;
5. upload results to artifact storage;
6. update task state;
7. maintain heartbeat.

SSH is permitted only for:

- initial provisioning;
- repair;
- emergency break-glass access;
- recovery of a completely disconnected node.

Create OPA policy:

routine_task_execution_via_ssh = deny

Before any routine SSH action, the system must prove:

- node agent unavailable;
- internal network unavailable;
- repair task exists;
- break-glass reason recorded.

Remove public SSH addresses from normal Agent Host configuration.
